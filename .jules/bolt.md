## 2024-05-06 - React referential equality edge case in lists
**Learning:** Using React.memo on a list item requires modifying its event handlers. If the parent passes inline closures (e.g., `onAdd={() => handleAdd(item)}`), `React.memo` will always fail shallow comparison because the function reference changes every render. The child MUST be refactored to accept generic stable handlers and its own identifiers.
**Action:** Changed `RelationCard` props to accept identifiers and stable `useCallback` functions.
## 2024-05-07 - O(1) hash map caching and module-level pre-sorting in InheritanceEngine
**Learning:** In heavily looped inference engines, repeatedly sorting static rules (`KNOWLEDGE_BASE`) and performing O(N) list scans to gather facts (e.g., counting valid heirs) introduces significant overhead. Replacing O(N) linear scans over `state.valid_heirs` with a scoped O(1) hash map cache (`_raw_counts`) populated at instantiation drastically improves fact evaluation speed. Crucially, dynamic state variables (like `excluded_relations`) MUST still be evaluated against these static counts at runtime rather than caching dynamic conditions directly, which risks staleness or schema violations if attached improperly to Pydantic models. Pre-sorting static arrays (`KNOWLEDGE_BASE_SORTED`) at the module level prevents redundant work on each function call.
**Action:** Implemented `_raw_counts` hash map cache in `InferenceEngine.__init__` and used it in `_get_fact_value`. Pre-sorted `KNOWLEDGE_BASE` to `KNOWLEDGE_BASE_SORTED` at module level and replaced dynamic sorting in `EnginePipeline.calculate`.
